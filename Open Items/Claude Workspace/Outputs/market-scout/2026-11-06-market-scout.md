### 1. A bad fortnight for the Claude Code supply chain: a trojanized extension, an email leak, and transcripts you didn't know were sent ⭐ WORTH A SESSION THIS WEEK
[StepSecurity: trojanized Claude Code extension delivered a persistent SSH backdoor](https://www.stepsecurity.io/blog/claude-code-extension-trojanized) · [Cursor security notice and check scripts](https://cursor.com/blog/claude-code-extension-security-notice) · [The Hacker News](https://thehackernews.com/2026/10/official-claude-code-vs-code-extension.html) ([HN 1011](https://news.ycombinator.com/item?id=50300683)) · [Issue #107757: Claude Code sends your email address to websites](https://github.com/anthropics/claude-code/issues/107757) ([HN 1210](https://news.ycombinator.com/item?id=50385272)) · [Gist: Claude Code sends each background agent's transcript to its model](https://gist.github.com/flamerix-ai/c3905705cc4205e5de3011fa2e74efce) ([HN 590](https://news.ycombinator.com/item?id=50284255)) · [CHANGELOG v2.1.317–318](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

- **Trojanized extension (Oct 29).** Builds 2.1.312 and 2.1.313 of the official Claude Code VS Code extension were pushed to **Cursor's** extension marketplace (macOS and Windows) between 09:27 and 20:35 UTC. The payload added an attacker SSH key to `~/.ssh/authorized_keys`, turned SSH on, opened a reverse tunnel, set up persistence (cron `@reboot`, a `com.apple.sysmond` LaunchAgent, or a `SysMon` scheduled task), and sent back the hostname, user, git email and the *names* of environment variables matching KEY/TOKEN/SECRET. Cursor's first estimate is up to 5,000 users. Per StepSecurity, Anthropic says the VS Code Marketplace, Open VSX and its own channels were not affected.
- **Email in the User-Agent.** Web and shell tool calls could carry the account email to third-party sites (the reporter blames it for daily scam mail). v2.1.317 adds a check that asks before a web or shell call sends your account email, and the issue thread says a built-in privacy mod now blocks it by default (it can be turned off in `/plugins`).
- **Background-agent transcripts** are periodically sent to the model (the gist's reading). Treat anything a background agent reads as something that leaves the machine.
- Also in v2.1.317: `/schedule` now **warns when a new cloud scheduled task gets connectors you didn't ask for**. In v2.1.318, `deniedMcpServers` URL entries also block matching connectors in cloud sessions.

**Why it matters to Ali:** your fleet runs unattended, holds the hub `.env` (every key in one file), and scouts curl the open web daily. The extension attack harvested exactly what your machines hold: env-var names, git identity, SSH access. The email leak is the same lesson from the other side: anything that goes out in a header goes to strangers. This run itself loaded dozens of connectors it never needed, which is the pattern the new `/schedule` warning targets.

**The session (~45 min): a credential-exposure check of the fleet.**
1. **Cursor:** if any Turner or home machine runs Cursor with the Claude Code extension, run Cursor's check scripts (link above) and look for an unfamiliar `svc-telemetry` line in `~/.ssh/authorized_keys`.
2. **Version:** confirm every machine is on Claude Code ≥ 2.1.317, so the email check and privacy mod are active.
3. **Your own scripts:** grep sosmon and the scout scripts for `User-Agent` and `alimam38`. Use a generic client name, never the account email.
4. **Connectors per routine:** open each scheduled task and remove the connectors it doesn't use. The smaller the set, the less a prompt-injected page can reach.
5. **.env blast radius:** list which keys each routine actually needs. Consider a per-lane env file, so a scout only ever sees SERPAPI_API_KEY.

### 2. Claude Duet: Anthropic ships the "proactive agent you message", the product version of your lane fleet
[Claude Duet product page](https://claude.com/product/claude-duet) ([HN 568](https://news.ycombinator.com/item?id=50186037)) · [Claude Duet article](https://claude.com/resources/articles/claude-duet) · ["Duet is the first personal-assistant harness that feels useful"](https://fig.blue/posts/duet-is-the-future/) ([HN 126](https://news.ycombinator.com/item?id=50292727)) · open-source analogue: [KKKKhazix/agent-autoloop](https://github.com/KKKKhazix/agent-autoloop) (3,473★ in 3 days)

Duet (announced Oct 21–22) is an always-on agent that works on its own cloud computer with your connectors. It sends a morning brief, flags what needs you in mail and calendar, drafts replies for approval, **finds unpaid invoices and drafts the reminders, prepares payroll for review, and gets contracts ready to send**. It names QuickBooks, Gusto, Docusign, Gmail, Slack and Notion among 6,000+ connectors. It asks before sensitive actions (sending, paying) and otherwise stays quiet. It runs on your existing Claude account (memory, skills, connectors). It's a **US research preview with a waitlist for Pro, Max and Ultra**; Team and Enterprise aren't included yet. agent-autoloop is a CLI agent that takes on background work and pings only "when it isn't sure", the same shape in open source.

**Why it matters to Ali:** this is your LOOP pattern (state file, objective gate, single ask) turned into a product, and it reaches straight into your Turner back office: QuickBooks, Gusto, invoices, a morning brief. Join the waitlist. When access arrives, run it side by side with the `morning` and invoice-review lanes for a week before deciding which lanes it replaces. Note the plan limit: if Turner is on Team or Enterprise, Duet is personal-account only for now, so keep Turner data out of it until that changes.

### 4. Release radar: Claude Code v2.1.305–318, the changes that touch your fleet (plus two deadlines)
[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

- **Deadline: Opus 4.8 fast mode is removed Nov 30, 2026** (deprecated Oct 30). After that, fast-mode requests on Opus 4.8 return an error with no fallback. Any routine pinned to Opus 4.8 with `/fast` should move to Opus 5.5 (v2.1.316).
- **Deadline reminder:** standalone Claude Design (claude.ai/design) closes **Dec 14** (from the Oct 20 digest).
- **Scheduled tasks:** cloud runs now **load the plugins enabled on your claude.ai account** (v2.1.314). Routines can set an **effort level** in the model picker (v2.1.312). `/schedule` warns about connectors you didn't ask for (v2.1.317). Runs stopped by auto mode for lack of a safety verdict now show as failed (v2.1.316). New scheduled tasks start on the org's default environment (v2.1.317).
- **Cowork cloud WebFetch:** a stalled request now fails after 300 s instead of hanging (v2.1.311). A 4xx or robots.txt refusal is a normal result, not a tool error (v2.1.307). A PDF over 100,000 characters now says how much was unread instead of silently truncating (v2.1.314). Fewer 5-minute waits per subagent on unapproved URLs (v2.1.305).
- **Cloud sessions:** a "No repository" start option, Chrome names for the built-in Chromium, and working `gh run view --log` (v2.1.318). New form and link cards for MCP elicitation, so a connector's sign-in or form request is no longer silently cancelled in unattended runs (v2.1.316–317).
- **Connectors:** Cowork cloud sessions no longer lose connectors after a restart when a plugin names an `agent` (v2.1.311).

**Why it matters to Ali:** the PDF fix matters for Populi invoices and board packets: long ones could have been cut off without warning. The effort-level picker lets cheap lanes (scouts, sweeps) run at low effort while report lanes stay high. The Opus 4.8 fast-mode removal is the only hard break in this list.
