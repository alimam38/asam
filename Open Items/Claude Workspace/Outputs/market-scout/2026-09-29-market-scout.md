### 3. Release radar: Claude Code v2.1.280–284 — fixes that land directly on your setup
[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) · [AGENTS.md-only-with-telemetry bug write-up](https://blog.szypowi.cz/p/claude-code-reads-agents.md-only-when-telemetry-is-on/) ([HN 485pts](https://news.ycombinator.com/item?id=49814947))

- **Skill namespace change (v2.1.282):** local skill folders, commands and MCP servers named in the `anthropic-skills` or `claude-ai` namespace no longer load. Only skills synced from claude.ai count, and `Skill(anthropic-skills:*)` allow rules now cover only synced skills. Your whole library lives under `anthropic-skills:`, so any local copy or custom server using that name will silently disappear.
- **Unattended safety (v2.1.281):** in auto mode or `--dangerously-skip-permissions`, a dangerous `rm` prompt now waits 2 minutes and then denies with a rewrite hint, so unattended sessions keep going instead of hanging. Server-side auto-mode review now also covers read-only and sandboxed shell commands.
- **Model governance (v2.1.283):** `deniedModels` and `availableModelsMatch: "exact"` managed settings keep new model versions blocked until you list them. Useful if you want the fleet to stay pinned while you evaluate pick #1.
- **MCP:** URL-mode elicitation on 2026-07-28-spec connections (browser-based auth flows), `/mcp reconnect all`, and resumed sessions now wait up to 10 s for a still-connecting server instead of failing with "No such tool available" — a failure your cloud runs have hit.
- **AGENTS.md** was only read when telemetry was on; fixed in v2.1.281 for Bedrock, Vertex, gateways and telemetry-off sessions.
- Also: "Prompt is too long" after compaction now re-compacts instead of failing; `/loop` self-paced updates are now written as visible text; interactive sessions now start in auto mode by default.

**Why it matters to Ali:** the namespace change and the MCP-reconnect fixes land directly on your skill library and your cloud-run failure modes; the `rm` timeout changes how an unattended run behaves when it hits a destructive command.

### 4. "Agent takes it to production" tooling: GoLive skill + Cloudflare's agentic `cf` CLI
[mikehasa/golive-skill](https://github.com/mikehasa/golive-skill) (1,083★ in 6 days) · [Cloudflare: Introducing cf, the agentic CLI for the entire Cloudflare API](https://blog.cloudflare.com/cloudflare-cf-cli-launch/) ([repo](https://github.com/cloudflare/cf), [HN 156pts](https://news.ycombinator.com/item?id=49879577)) · adjacent: [Docker cloud sandboxes](https://www.docker.com/c/sbx-promo/)

GoLive is an open-source Agent Skill plus a zero-dependency Node CLI that takes an agent-built app live on *your own* accounts: hosting (Vercel/Netlify), database (Supabase/Neon), DNS (Porkbun/GoDaddy), email (Resend), test-mode Stripe and Supabase auth. It runs detect → plan → **approve** → apply → verify, then records what it created, checks for drift and can tear it all down. Every write needs an approved plan id, DNS, deletes and live-mode steps each need their own confirm flag, and credentials never appear in arguments or logs. The README is honest that it's early alpha and that an agent already logged into a provider can bypass it. Cloudflare's `cf` makes the same bet from the vendor side: JSON-default output built to save context, command search built for agents, and a TypeScript config for the whole platform.

**Why it matters to Ali:** this is the missing last mile for Plumbline-style builds — Claude can write the dashboard, but getting it onto hosting, a database and a domain with approvals and a teardown path is where solo projects stall. GoLive's plan/approve/verify/record pattern is also a good template for your own fleet's write steps, and it pairs naturally with pick #2.
