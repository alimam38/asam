### 2. Claude Code's "Don't ask again" writes secrets into `.claude/settings.local.json`, and 1,122 public repos committed them
- **What:** Apiiro found that when you approve a command containing a password or key with "Yes, and don't ask again", Claude Code saves the literal command, secret included, as a permission rule in `.claude/settings.local.json` inside the project. They found 104k of those files on public GitHub; 1,122 contain real secrets. Counting git history, shared settings, chat transcripts and **agent memory files (`MEMORY.md`)**, they found 2,539 secrets in 1,994 repos. Separately, Claude Code 2.1.321 fixed **MCP OAuth refresh tokens being sent to another host on a redirect**, plus two cases where Bash skipped the sandbox or the permission prompt.
- **Why it matters to Ali:** `alimam38/asam` is the memory for your cloud jobs, and the hub keeps credentials in one `.env`. Checks: (a) search the repo (including history) for `.claude/settings.local.json`, `MEMORY.md` and handoff notes that hold tokens; (b) add `.claude/settings.local.json` to `.gitignore`; (c) refer to keys as `$VAR`, never as literals, in approved commands; (d) update Claude Code to ≥2.1.321 on the Windows machine. This takes about 15 minutes, and Apiiro's guidance is to rotate anything you find.
- **Links:** [Apiiro research](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again) · [HN (424 comments)](https://news.ycombinator.com/item?id=50407882) · [CHANGELOG 2.1.321](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

### 3. Anthropic research: "The components of agent memory" (dreaming, wikis, small injected layer)
- **What:** Anthropic research (Nov 6) splits agent memory into four layers: transcripts, notes Claude writes, structured representations such as wikis, and the context injected into every session. Findings: "dreaming" (an idle-time pass that checks notes against transcripts, merges duplicates and builds wikis) improves results. Fixed rules like "record only failures" *hurt* frontier models. Wikis plus search beat search alone and save tokens. Keep the injected layer small: Claude Code loads only the first 200 lines / 25 KB of `MEMORY.md`. Artifacts shipped with it: a [dreaming cookbook](https://platform.claude.com/cookbook/managed-agents-cma-dreaming-with-a-dynamic-workflow), a [knowledge-wiki quickstart](https://github.com/anthropics/claude-quickstarts/tree/main/managed-agents/knowledge-wiki), Managed Agents [dreams](https://platform.claude.com/docs/en/managed-agents/dreams) and [memory directory](https://platform.claude.com/docs/en/managed-agents/memory) docs, and CL-Bench 1.0.
- **Why it matters to Ali:** Your setup already follows this pattern: MASTER.md as the boot block, lane OS files as the wiki, seen-index and ledgers as transcripts. The paper gives evidence for two specific changes: cap MASTER.md/boot blocks at a hard size, and add a scheduled "dreaming" pass that reconciles each OS file against recent run outputs. The fixed-rules finding also argues for loosening over-prescriptive extraction rules in os-architect.
- **Links:** [Anthropic research post](https://www.anthropic.com/research/components-of-agent-memory) · [HN](https://news.ycombinator.com/item?id=50402212)

### 4. shanselman/sandbox-mcp: throwaway Windows machines as an MCP server
- **What:** Scott Hanselman released an MCP server and CLI (created Nov 6, 393★ / 19 forks, actively pushed) that drives Windows Sandbox. An agent can start a clean, disposable Windows VM, install and test something in it, and then throw it away.
- **Why it matters to Ali:** It gives agent-driven installs and tests on your Windows PC a contained place to run. The system-optimizer "missing apps" step and any Docker/NAS tooling trials could run in the sandbox instead of on the host, which cuts the risk the Apiiro item highlights. It has a credible author, a real artifact and a healthy star/fork ratio. Requires Windows 10/11 Pro or Enterprise with Windows Sandbox enabled.
- **Links:** [GitHub](https://github.com/shanselman/sandbox-mcp) · GitHub topic:mcp-server search
