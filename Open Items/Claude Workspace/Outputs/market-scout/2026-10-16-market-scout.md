### 1. Claude Dashboards (beta) and Claude Motion: Anthropic now builds live dashboards over your connectors ⭐ WORTH A SESSION THIS WEEK
[Reuters: Anthropic launches dashboard, animation tools for Claude](https://www.reuters.com/technology/anthropic-launches-dashboard-animation-tools-claude-2026-10-08/) · [Tabular Editor: What are Claude Dashboards?](https://tabulareditor.com/blog/what-are-claude-dashboards) · [RuntimeWire: live dashboards and editable animations](https://runtimewire.com/article/anthropic-claude-dashboards-motion-beta) · [FourWeekMBA: Dashboards and Motion, Docs exit beta](https://fourweekmba.com/ai-anthropic-adds-claude-dashboards-and-motion-docs-exit-beta/) · [r/analytics: what is changing with Claude dashboards?](https://www.reddit.com/r/analytics/comments/1x4dyf4/what_is_changing_with_claude_dashboards/) · X via SerpAPI: [Dashboards querying a Power BI semantic model live via DAX](https://x.com/kurtbuhler/status/2108535970287022395)

Launched Oct 8. You connect a data source, ask a question, and Claude builds a **live** dashboard, with the query behind every chart shown in a sidebar. Data comes in through **connectors, which are MCP servers**: built-in ones or custom ones you supply (Tabular Editor). One demo shows Dashboards querying a Power BI semantic model directly. Practitioners' early read (Reddit, LinkedIn) is "better than before, good for basic analysis, not yet a Power BI or Tableau replacement." Claude Motion turns business data into short animated explainers. Coverage also says Claude Docs is out of beta.

**Why it matters to Ali:** this lands squarely on Plumbline's core idea (dashboards and SIS overlays for small institutions). A registrar or business office with a Claude seat and a Populi or Postgres connector can now get a live, query-backed dashboard without a vendor. The upside: your own Turner reporting (enrollment, Talbot Hall balances, B&F monthly KPIs) may be quicker to stand up this way than to hand-build. The threat: Plumbline's moat has to be what a generic dashboard can't supply, such as curated higher-ed metric definitions, accreditation-ready views, governed access to SIS data, and support for institutions with no data person.

**The session (~60–90 min):** point Claude Dashboards at one real Turner dataset you already reach through a connector (the Meridia Postgres DB or a Populi export), and rebuild one report you produce by hand today (e.g. the Talbot unpaid-balances view or a B&F monthly KPI table). Write down what it gets right, where it breaks (joins, term logic, FERPA-sensitive fields, refresh behavior), and what a small-college buyer would still pay Plumbline for. You come out with a decision: either build Plumbline as a governed metric layer plus MCP connector that *feeds* Claude Dashboards, or keep competing with them.

### 4. Release radar: Claude Code v2.1.285–301, the fixes that hit your setup
[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)

- **Cowork cloud sessions:** Write/Edit no longer report success for a path on your own computer when the file never arrived (v2.1.300). This failure could silently drop deliverables. Also fixed: cloud sessions running an **old version of an account plugin** after you change it on another device (v2.1.299); sessions hanging 5 min per turn when org policy can't be read; and already-answered messages re-running after a restart.
- **Scheduled tasks and DST:** fixed scheduled tasks and loops firing again after every turn, or firing early, during the repeated hour when daylight saving time ends (v2.1.299). US DST ends **Sun Nov 1**. Also fixed: scheduling tools announcing the wrong next-run minute. Routine runs now publish private artifacts without asking (v2.1.292/295).
- **Skills:** a clearer "Unknown skill" error when Claude wrongly adds the `anthropic-skills:` prefix (that's your whole library's namespace); `/reload-skills` restores skills after compaction; claude.ai skill sync now checks every ~40 min instead of 10 when idle (v2.1.293).
- **MCP:** connectors now negotiate the **2026-07-28 spec by default** (opt out with `MCP_PROTOCOL_NEGOTIATION=legacy`). Allow rules now match only the exact server named (`mcp__a` no longer covers `a__b`). MCP proxies in cloud sessions no longer follow redirects. Tool descriptions are cut at 4,096 characters, up from 2,048.
- **Safety for unattended runs:** hooks can set `onFailure: "block"` (a hook that can't run blocks the action instead of letting it through). `UserPromptSubmit` hooks now run before a skill expands. Retry-watchdog limits are now configurable for 429/529 errors.

**Why it matters to Ali:** the silent-false-success fix and the DST fix both affect your unattended fleet directly. If a scheduled task fires twice or early around Nov 1, this explains why. The stale-plugin fix explains any "I changed the skill but the cloud run used the old one" moments.
