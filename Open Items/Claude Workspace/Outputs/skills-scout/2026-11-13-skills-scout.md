## Official / Tier 1

1. **Claude Code 2.1.323: Code Mode (experimental) + plugin version pinning + a big permission/sandbox hardening batch**. What's new: Code Mode is an opt-in mode where Claude writes JavaScript to call its tools, and an org admin can turn it off. `plugin.json` gets `engines["claude-code"]`: a plugin is not installed, updated or loaded outside its stated version range. `claude plugin validate` now type-checks TypeScript hooks (`--strict` fails on findings). Long hooks in `claude -p` and SDK sessions send a progress heartbeat every 30s. Artifact uploads accept `.docx`. There are also about 30 permission and sandbox fixes: Bash wildcard and sudo/env wrapper rule gaps, a Write/Edit vs `Read` deny gap, auto mode falling back to Manual when auto is unavailable, and "don't ask again" no longer offered for writes to `.git` and `.claude`. **Why it matters:** this is your skill-forge and plugin-curation lane. `engines` plus validator type-checks are cheap guardrails for the skills and plugins you ship. The hook heartbeat stops long hooks in headless and scheduled runs (like this scout) being killed as "hung". The permission fixes also close gaps that last week's GitGuardian `settings.local.json` finding touched. **Trust:** Anthropic-verified, from github.com/anthropics/claude-code CHANGELOG.md. The Code Mode docs page (code.claude.com/docs/en/code-mode) did not load for this scout, so check how it works before enabling.

2. **Claude Code 2.1.321–2.1.322: MCP OAuth secret-leak fix + `claude remote-control --settings`**. 2.1.321 fixes MCP OAuth requests sending refresh tokens to another host when a server redirected them. It also fixes `cp`/`mv`-into-directory writes skipping deny rules, and PreToolUse hook `ask` reasons being lost or misattributed when several hooks fire. It adds `--settings <file>` to remote-control, which applies one settings file to every session it starts. 2.1.322 adds fast mode on Vertex. (Fable 5.2 as the default Fable model is already in the index from 11-10.) **Why it matters:** if you use any third-party OAuth MCP servers (Composio, Dropbox and others), update. The hook `ask`/`defer` fixes are the exact mechanism behind Aegis-style approval gates. **Trust:** Anthropic-verified (CHANGELOG).

## Aegis / governance

6. **AGP: Agent Governance Protocol (agp.bian.org / agp-protocol.dev)**. An open protocol for autonomous agents: fail-closed execution, capability tokens, a hash-chained ledger, and policy verdicts of `allow`, `require_approval`, `deny` and `quarantine`. `require_approval` pauses a task in `APPROVAL_PENDING` until a human signs off. SDKs: Python `agp-sdk`, npm `@agp-protocol/sdk`, and `agp-mcp`. It maps to EU AI Act Articles 9, 12, 13 and 14. **Why it matters:** it closely matches Aegis's governance-alert approvals and audit trail, and it can serve as a reference vocabulary or interop target for the FastAPI engine. If the BIAN link is real (BIAN is a banking-architecture standards body), it is also relevant to Meridia's "governance-not-guardrails" patent framing as prior art. **Trust:** unknown/community, install with caution. The page shows no date or license, and the BIAN affiliation is not verified.

7. **SidClaw governance MCP server / approval layer** (sidclawhq/platform; launched around Mar 2026, backfilled because it was not in the index). An approval step for agent actions (`allow`, `approval_required` or `deny` per action; one-click approve or deny), a hash-chain audit trail, and Apache-2.0 TypeScript and Python SDKs. Listed on Glama and mcpservers.org. Free during early access, with paid tiers listed from CHF 199/mo. **Why it matters:** a working Aegis comparable. Use it to benchmark the approval UX and audit-chain design before building more of your own. **Trust:** known directory listing (Glama) for an unknown vendor, so install with caution. Its claims (705 tests, FINRA/HIPAA demos) are self-reported.
